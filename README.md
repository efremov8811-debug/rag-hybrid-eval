# RAG по технической документации

Поиск ответов по документации поставщика контрольно-измерительных приборов:
каталог, поверка, гарантия, договорные условия, карта регистров Modbus.

Работает целиком локально на CPU. Без внешних API, без GPU, без докера.
Нужен только Python 3.11 и около 800 МБ на модели.

## Зачем это написано

Чтобы измерить, что реально даёт каждый слой retrieval-пайплайна, а не
принять на веру, что «гибридный поиск лучше». Поэтому поиск разбит на три
режима, которые можно включать по отдельности и сравнивать на одном наборе
вопросов.

## Результаты замера

25 размеченных вопросов, 9 документов, 39 чанков. Процессор, без GPU.

| Режим | Recall@1 | Recall@3 | Recall@5 | MRR | Задержка |
|---|---|---|---|---|---|
| Только векторный поиск | 0.68 | 0.80 | 0.84 | 0.737 | 5 мс |
| + BM25, слияние RRF | 0.88 | 0.96 | 1.00 | 0.921 | 5 мс |
| + кросс-энкодер | 0.96 | 1.00 | 1.00 | 0.980 | 1822 мс |

Воспроизводится командой `python evaluate.py`.

Как читать таблицу. Лексическая ветка добавляет 20 пунктов Recall@1 бесплатно
по времени. Реранкер добавляет ещё 8 пунктов, но дороже в 360 раз, поэтому в
продакшене он оправдан не всегда: при потоке запросов его включают только для
тех, где гибрид вернул близкие оценки.

## Почему векторный поиск промахивается

Все четыре устойчивых промаха чисто векторного режима — одного типа.

| Вопрос | Что вернул вектор |
|---|---|
| Скидка при сдаче в поверку партии из 60 приборов | каталог расходомеров |
| Сколько стоит выезд инженера на объект | каталог расходомеров |
| Покрывает ли гарантия подачу 48 вольт на ДД-100 | каталог датчиков давления |
| Когда истекает свидетельство на термопары | каталог термопар |

Модель цепляется за тему вопроса и уходит в каталог, где эта тема описана
подробнее, вместо документа, где лежит ответ. Вопрос про 48 вольт — про
гарантию, а не про датчик; вопрос про свидетельство — про сертификаты, а не
про термопары. BM25 вытягивает такие случаи, потому что держит точные токены:
«48 В», «60», «выезд».

## Устройство

```
docs/              корпус, markdown с заголовками
rag/chunking.py    разбиение по заголовкам, окно с перекрытием
rag/lexical.py     BM25 с русским стеммингом
rag/search.py      векторный поиск, RRF, кросс-энкодер
ingest.py          сборка индекса
ask.py             вопрос к корпусу
evaluate.py        замер качества
eval/questions.json  размеченный набор
```

Модели: `paraphrase-multilingual-MiniLM-L12-v2` (384 измерения, 220 МБ) для
эмбеддингов, `bge-reranker-v2-m3-int8` (570 МБ) для переранжирования.
Квантованная версия реранкера взята вместо fp32 на 2,3 ГБ: на этом корпусе
разницы в качестве не видно, а памяти нужно вчетверо меньше.

## Принятые решения

**Заголовок секции дописывается в начало каждого чанка.** Без него фрагмент
«Межповерочный интервал: 5 лет» теряет привязку к прибору и всплывает в любом
вопросе про интервалы поверки.

**Слияние веток через RRF, а не взвешенной суммой.** Косинусная близость и
оценка BM25 живут в разных шкалах. Нормировать их друг к другу означает
подобрать коэффициент под конкретный корпус и потерять его на следующем.
RRF складывает обратные ранги и от шкалы не зависит.

**Стемминг только для кириллицы.** Артикулы вида ДД-200-Н, обозначения
Pt1000 и номера регистров 40030 стеммер портит, после чего точный поиск по
ним перестаёт работать.

**В кросс-энкодер уходит 12 кандидатов, а не все 20.** Подобрано замером:
на 12 качество то же, задержка втрое ниже.

## Честные ограничения

Корпус синтетический: документы написаны специально для этой задачи, в них
нет шума реальных выгрузок — сканов, таблиц в вёрстке, повторяющихся шапок.
На реальном корпусе цифры будут ниже.

Набор из 25 вопросов мал для устойчивых выводов: разница в один вопрос
сдвигает Recall@1 на 4 пункта. Для продакшена нужен набор хотя бы на
несколько сотен вопросов, размеченный не автором системы.

Один вопрос набора пришлось переразметить: ответ про срок действия счёта
честно присутствует и в документе об оплате, и в каталоге термопар. Это
типичная ошибка разметки — сначала она выглядела как промах поиска.

Генерация ответа (`--answer`) сделана заглушкой поверх внешнего API и в
замере не участвует: меряется retrieval, а не формулировки модели.

## Запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python ingest.py
.venv\Scripts\python evaluate.py
.venv\Scripts\python ask.py "сколько стоит поверка расходомера"
```

Первый запуск скачивает модели, дальше всё работает офлайн.

Для генерации ответа задайте ключ и добавьте флаг:

```
set DEEPSEEK_API_KEY=...
.venv\Scripts\python ask.py "..." --answer
```
